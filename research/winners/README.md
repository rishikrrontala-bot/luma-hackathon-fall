# Winner briefs: how they were verified

**Read this first.** This cloud session's network policy blocks direct page loads from
`devpost.com`, `*.devpost.com`, `youtube.com`, `joinluma.org` and most other hosts
(WebFetch and curl both return `EGRESS_BLOCKED` / proxy 403; see PROGRESS.md). Only web
**search** works. So no brief below could be opened in a browser the way the hackathon-win
skill asks. Instead each winner was confirmed from the search index of an **official** source
whose own page title or indexed text states the prize (a `congressionalappchallenge.us` winner
page, a `technovationchallenge.org` results page, a `blueoceancompetition.org` interview page).

The verification boxes in each brief are ticked only for what was actually confirmed:

- **page loaded**: ☐ in every brief (egress blocked). Rishik can re-check each link in a normal browser in a minute.
- **prize stated on page**: ☑ only when the official page's indexed title/snippet states the prize.
- **video played**: ☐ in every brief (YouTube blocked).

**Why these winners.** The skill's priority order is prior editions → same organizer → same
sponsors → same domain. LUMA (a Redmond, WA student nonprofit) has run at least seven
Devpost events since 2024, but none of their project galleries is published or indexed
(the April–May 2026 gallery reads "The hackathon managers haven't published this gallery
yet"), and no LUMA winner is named anywhere the search index reaches. There are no
sponsor tracks. So the briefs come from the closest same-domain competitions: **teen**
builders, a **working product plus a pitch**, judged partly on **business viability**:
